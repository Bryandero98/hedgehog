lease with no concurrent `claim` call in the interim could reach
`verify` looking legitimately leased. Fixed with a new
`src/db/commitLock.mjs` filesystem mutex (wraps gate 1's diff and gate
2's classify-and-commit separately, `verify_command` itself stays
unlocked so verification doesn't serialize on test runtime), a
neighbor-scope exclusion in the gate plus always re-diffing to the
task's own `scope_globs` right before commit (rather than committing
the raw unrestricted touched set), and reusing `claim.mjs`'s existing
SQL-side lease-expiry check inside `claimForVerify`. Verified with a
real two-process fork test (confirms actual cross-process mutual
exclusion, not just per-call serialization) plus direct `verifyTask`
smoke tests for both the false-positive fix and that a genuine
violation still blocks.
