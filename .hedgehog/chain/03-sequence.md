# Sequence

## Step 2 — Section list (AIDA beat-map)

Derived from the subject statement (get the developer to run
`npx @skyf0xx/hedgehog init` by recognizing the rot failure mode and
seeing Hedgehog's checked-step process as the fix) and the note-timing
spec (top: sober; heart: disciplined/in-control; base: load-bearing/
earned-relief; peak: failure-mode recognition; ending: quiet procedural
CTA).

1. **Hero** — Attention
2. **Failure-mode recognition** — Interest/Desire pivot (peak moment)
3. **Mechanism explanation** — Desire (logos, reason-why)
4. **Proof points** (per-step verification, small-step build order) — Desire (logos, evidence)
5. **Close/CTA** — Action (ethos, ending treatment)

Five sections. No more: Miller's Law caps what a single scroll should
hold, and every additional section would need its own AIDA slot — there
isn't a sixth beat to justify one.

## Step 3 — Transitions

| From → To | Transition type | Reason |
|---|---|---|
| — → Hero | (page load, no prior panel) | n/a |
| Hero → Failure-mode recognition | **Subject-to-subject** | Same scene (the reader's own project), camera moves from the product's claim (hero) to the reader's felt experience (rot) — McCloud's subject-to-subject holds the scene constant while reframing who/what is in focus. Not scene-to-scene: there's no location/time jump, just a reframe onto the reader. |
| Failure-mode recognition → Mechanism explanation | **Action-to-action** | The failure-mode section ends on a felt problem (pathos); the mechanism section is the single action that answers it (the step-check catching what rot exposed) — one continuous action broken into two panels, cause then response. Not scene-to-scene: no setting change, this is the direct next beat of the same throughline. |
| Mechanism explanation → Proof points | **Aspect-to-aspect** | The mechanism was explained as one claim; proof points show facets of that same mechanism (planning, per-step checks, correction protocol) without advancing time or action — McCloud's aspect-to-aspect is for surveying facets of one place/idea, which is exactly what a proof list is. |
| Proof points → Close/CTA | **Scene-to-scene** | This is the one deliberate large jump: from evidence-gathering (logos) to the reader's next procedural moment (ethos, the install step) — a real scene change in register and time (present evidence → next action the reader takes), earning scene-to-scene rather than defaulting to it. |

Four transitions, four distinct types, no repeats — confirms the
constraint against defaulting every jump to scene-to-scene.

## Step 4 — Weight, spacing, beats

| Section | Relative weight | Spacing (gutter) | Beat structure |
|---|---|---|---|
| **Hero** | Medium (1x) | Wide margin above/below — first threshold, per Architecture's procession/threshold borrowing; sets the "generous density" token before any claim is made | **Setup only** (1 beat): subject-statement claim stated plainly, logos-leaning per the voice spec's ethos/pathos/logos audit. No build/payoff here — payoff is deferred to the failure-mode section by design (Chekhov's gun: the hero's claim is the plant, failure-mode section is the payoff). |
| **Failure-mode recognition** | Heaviest (1.5x) | Grid break + `--color-signal` release happens here (Step 4a/Step 6's single licensed exception) — the one section allowed to break the strict grid, so its spacing is deliberately irregular against the page's otherwise-uniform gutter | **Setup / Build / Payoff** (3 beats): setup names the pattern generically ("AI code works, then—"), build stacks the specific symptoms (drifts, breaks, becomes unreviewable) in short declarative sentences per the voice spec's sentence-rhythm rule, payoff is the recognition spike itself — the moment the reader sees their own project. This is the peak moment, confirmed placed here (see Step 5). |
| **Mechanism explanation** | Medium-heavy (1.25x) | Returns to strict grid immediately — the snap back to regularity itself signals "this is the fix," structure re-asserting itself right after the one break | **Setup / Payoff** (2 beats): setup states the mechanism claim (checked-step process), payoff is the reason-why per Hopkins discipline ("because each step gets checked before the next starts — not because the model remembers the last one"). No build beat needed — this section earns trust by precision, not by accumulation. |
| **Proof points** | Heaviest by count, lightest per-unit (1.5x total, split across 3 incidental sub-panels) | Tight, even gutter between the three proof items (planning intake, per-step verification, Correction Protocol) — consistent spacing signals these are parallel facets, not a sequence with its own internal drama | **Build only**, repeated 3x (1 beat each, no individual setup/payoff — the section's payoff is collective, arriving only at the transition into Close/CTA): each proof point is a single-node incidental signature-element mark (Step 6) confirmed lit as the reader scrolls past it — the spine's accumulating-fill behavior is the section's real payoff, deferred to be read cumulatively rather than per-item. |
| **Close/CTA** | Light (0.75x) | Widest spacing on the page — deliberate empty space around the install command, enacting "quiet and procedural" rather than crowding it with reassurance copy | **Setup / Payoff** (2 beats): setup is the completed signature-element chain (all nodes filled — the motif's resolution, per Step 6's persistence spec), payoff is the install command itself presented as the next small checked step, imperative mood permitted here only, per the voice spec. No build beat — a build beat would read as a pitch ramp, contradicting the ending treatment. |

Weight order (heaviest to lightest): Failure-mode recognition (1.5x) ≈
Proof points (1.5x) > Mechanism explanation (1.25x) > Hero (1x) >
Close/CTA (0.75x). The page's mass sits in the middle (recognition +
evidence), tapering at both ends — consistent with "sober, not hyped" at
the top and "quiet, procedural" at the close; neither end competes for
the heaviest emphasis.

## Step 5 — Peak moment and ending treatment confirmation

- **Peak moment** (landing-strategist: recognition spike, not hero, not
  CTA) lands in **Failure-mode recognition**, section 2 of 5 — matches
  exactly. It is also the section carrying every "earned exception" from
  upstream: the one grid break (4a), the one `--color-signal` release
  (Step 5 token system), the one pathos-only section (4b's ethos/pathos/
  logos audit), and the one lit mid-chain node (Step 6). No conflict —
  all four upstream artifacts independently pointed at the same section,
  which is why it also carries this sequence's heaviest weight (1.5x).
- **Ending treatment** (landing-strategist: quiet, procedural, install
  command as next small checked step) lands in **Close/CTA**, the final
  section — matches exactly. Confirmed by: lightest weight (0.75x, no
  crescendo), widest spacing (quiet), completed signature-element chain
  (resolution, not a new climax), and the only section where imperative
  mood is licensed (voice spec) applied to exactly one line (the install
  command), not the whole section.

No conflicts to flag — natural pacing agreed with both placements.

## Self-test

- Every transition type has a stated reason tied to McCloud's taxonomy,
  not "default": confirmed in Step 3's table — subject-to-subject,
  action-to-action, aspect-to-aspect, scene-to-scene, each with a
  one-line reason distinct from "that's the default."
- Chekhov's gun: the hero's claim (setup, no payoff in-section) pays off
  in the failure-mode section; the signature element's single lit node
  in the peak-moment section pays off as the completed chain in Close/
  CTA; the strict-grid break in the peak-moment section pays off by the
  snap-back to grid in Mechanism explanation (proving the break was
  deliberate, not a lapse). No introduced element lacks a stated payoff.
- Whole-composition check: weight tapers Hero (1x) → peak at Failure-mode
  (1.5x) → sustained at Proof points (1.5x) → Close (0.75x) — one rise,
  one sustained plateau, one deliberate taper, read as a single arc
  rather than five independent panels. Transition types don't repeat
  consecutively, so no stretch of the scroll reads as monotonous.
- Peak moment and ending treatment are both placed (Step 5), not
  omitted, and both confirmed against landing-strategist's spec with no
  unresolved conflict.
